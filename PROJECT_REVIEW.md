# Project review

Review performed on 2026-07-26.

## Fixed

- Consolidated the former top-level `core/` and `v2/` packages into the
  conventional `src/visual_automation/` package.
- Updated all internal imports, tests, and launch wrappers for the new package.
- Normalized `wc-fossil` filenames and folders to import-safe `wc_fossil` names.
- Added `pyproject.toml` with package metadata, Python version, dependencies,
  pytest discovery, and Ruff configuration.
- Added `requirements-dev.txt` for test and lint tooling.
- Restricted supported Python to 3.11–3.12 because the required
  `rapidocr_onnxruntime` package has no Python 3.13-compatible release.
- Expanded `.gitignore` for virtual environments, build output, tool caches,
  runtime configs, logs, and generated calibration images.
- Removed generated bytecode, `.DS_Store`, runtime settings, debug screenshots,
  and the two committed Motherlode calibration screenshots.
- Confirmed that `.venv/` is ignored and was never tracked. Keeping it inside
  the checkout is convenient; keeping it elsewhere is equally valid.
- Validated every example JSON config, compiled all Python modules, exercised
  `--help` on every automation launcher, and ran all 13 unit tests.

## Retained intentionally

- `templates/` image assets are runtime inputs, not generated build artifacts.
- Empty template directories represented by a `README.md` document calibration
  requirements for active flows.
- `logs/.gitkeep` and `config/.gitkeep` preserve runtime directories in a fresh
  checkout.
- Thin files in `scripts/` remain useful stable CLI/Finder entry points.

## Possibly unused — decide before deleting

These modules have no current callers outside their package export surface:

- `src/visual_automation/core/logger.py`
- `src/visual_automation/core/state_machine.py`
- `src/visual_automation/core/input.py`

They are coherent framework extension points, so this review did not delete
them. If no planned flow will use the logger/state machine or combined input
facade, all three can be removed along with their exports from
`src/visual_automation/core/__init__.py`.

## Remaining engineering opportunities

- Several flows duplicate bank-open/deposit/withdraw/close orchestration.
- Some flows still duplicate template-click and tick-wait helpers.
- The control panel is a single large Python file with embedded HTML; splitting
  its frontend assets would improve maintainability if the UI grows.
- Visual flows are inherently environment-dependent. Unit coverage currently
  protects shared calculations and macOS Quartz behavior, but each automation
  still needs dry-run calibration against the target client.

The existing local `.venv` uses Python 3.13. The current tests and CLI parsing
pass there, but recreate it with Python 3.11 or 3.12 before relying on OCR or
reproducible clean installs.
